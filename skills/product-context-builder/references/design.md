# DESIGN.md guide

`DESIGN.md` should describe the system that exists in the repository. Inspect tokens and components before writing prose.

Document:

- creative north star for the UI
- source-of-truth token and component paths
- colors with semantic usage and prohibited usage
- typography roles and hierarchy
- spacing, shape, elevation, and layout rules
- component inventory with reuse guidance
- interaction, focus, responsive, and accessibility behavior
- UI-specific do and avoid rules

Retain the repository's native token format when accuracy depends on it. When evidence conflicts, show the conflict instead of normalizing it silently. Missing design decisions should become questions, not invented tokens.
