# Project skills guide

Create a skill when a team repeats a task and the right instructions should load only for that task.

A useful skill has:

- a short, discriminating name
- a description that states the job and when it applies
- the non-obvious workflow and decision criteria
- references or templates only when they materially improve the task
- a clear stopping point and review boundary

Good candidates include creating a PRD, documenting a component, auditing token usage, reviewing UI against product principles, or preparing a release.

Do not turn a single project fact into a skill. Stable project facts belong in the relevant context file; one-off requirements belong in the task.
